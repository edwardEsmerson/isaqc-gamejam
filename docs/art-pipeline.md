# Demo art pipeline

The current demo's 32 PNGs are original, hand-authored pixel patterns generated
locally by `scripts/generate-demo-art.py`. The script uses only Python's standard
library: it needs no Pillow, network access, PixelLab, random seed, or external
artwork. The character Fleabag is small, pink-haired, and wears a white T-shirt
and blue jeans. Tiles, story props, decorations, and the observatory background
use the same authored palette.

## Regenerate and validate local art

From the repository root, run:

```bash
python3 scripts/generate-demo-art.py
python3 scripts/generate-demo-art.py --check
```

The generator writes PNGs and stable Unity `.meta` files to
`unity/Assets/Art/Generated/Demo/`. It records dimensions and SHA-256 hashes in
`unity/Assets/Art/Source/demo-art-manifest.json`; `--check` verifies the output
against the script without writing files. Keep the manifest and generator as
provenance/source; generated PNGs are what Unity imports.

For a quick layout illustration, run `python3 scripts/generate-demo-preview.py`.
It composites the production art using camera scale, platform rectangles, and
actor positions read from `DemoProjectBuilder.cs`, and writes
`docs/images/demo-preview.png`. It uses the same standard-library Canvas/PNG
encoder, adds no dependency, and is not a Unity render or a gameplay screenshot.
Use `python3 scripts/generate-demo-preview.py --check` to verify the checked-in
preview matches its sources.

## Replace or add sprites

- Match the existing scene scale: 16 × 16 pixel environment tiles at **16 PPU**
  and a fixed whole-room reference frame of **640 × 360 pixels**. The background
  art is also 640 × 360; do not use the old 320 × 180 reference.
- Import pixel art as Sprite (2D and UI), with a centered pivot, Point filtering,
  mipmaps off, and uncompressed texture data. Keep transparent pixels where
  needed and preserve consistent animation frame dimensions.
- The builder refers to sprite names in `Assets/Art/Generated/Demo/` (for example
  `Characters/fleabag-idle-0`). Keep those names when replacing art, or update
  `DemoProjectBuilder.cs` and the linked prefab sprite arrays as well.
- Tiles use Grid colliders for terrain. Keep art aligned to tile boundaries and
  avoid baking collision assumptions into transparent sprite outlines.

Use Aseprite optionally to inspect or edit frames; it is not installed by this
repository. Do not copy Celeste or other protected game art.

## Optional PixelLab MCP workflow

PixelLab is a hosted service, not a Unity package. This repository configures
its remote MCP server for OpenCode in `opencode.json`, using a token from the
`PIXELLAB_API_KEY` environment variable. It also has a Codex configuration
template at `config/pixellab.codex.toml` and a setup helper
(`sh scripts/setup-pixellab.sh`). Configuration does not itself authenticate a
client. No PixelLab credentials or tools were available in the session that
authored the current demo art; none of these PNGs were generated by PixelLab.

For OpenCode, set the token in the terminal that launches it. In Bash, enter it
without putting it in shell history:

```bash
read -r -s -p 'PixelLab API token: ' PIXELLAB_API_KEY
printf '\n'
export PIXELLAB_API_KEY
opencode
```

Quit and restart OpenCode after setting the variable or changing its config;
the running session does not reload MCP configuration. Check the MCP connection
in the new session before requesting artwork.

The configuration uses the official
[PixelLab MCP](https://www.pixellab.ai/mcp) endpoint
(`https://api.pixellab.ai/mcp`) with bearer-token authentication.
For Codex, the helper adds the shared template to `.codex/config.toml`; supply
`PIXELLAB_API_KEY` to the Codex process and start a fresh trusted-project session
(see the [Codex MCP guide](https://developers.openai.com/codex/mcp/)). A configured
server is not an authenticated session. Never put tokens in source, prompts, or
committed config. PixelLab account access/credits are separate from the game;
the game does not call it at runtime.

If future art is generated or sourced elsewhere, record creator/source and
applicable terms in `THIRD_PARTY.md` before it enters the project.
